# 004 — Value equality on generated models

## Context

Several Handlers (`SwitchHandler`, `WeatherHandler`, `SafetyHandler`, `DomeHandler`,
`FilterWheelHandler`, `RotatorHandler`, `GuiderHandler`, `FocuserHandler`, `MountHandler`,
`FlatPanelHandler`, `CameraHandler`) skip emitting a `device-info` event when NINA's internal
polling produces no actual change:

```csharp
if (data.Equals(lastData)) return;
```

This only works if `Equals` does value comparison. The models these handlers build
(`SwitchDeviceInfoData`, `CameraDeviceInfoData`, etc.) are generated by quicktype into
`Generated/EmitterModels.cs` from `schema/schemas/*.yaml` via `./schema/build.sh all`.
quicktype's C# target (`quicktype --lang csharp --help`) has no record option — it only ever
emits plain `class`, which falls back to `object.Equals` (reference equality). Comparing the raw
NINA SDK types (e.g. `SwitchInfo`) has the same problem, since those aren't ours to change either.
Swift-style synthesized struct equality, or a C# `record`, isn't reachable through the generator.

---

## Decision

Each generated model type gets a **hand-written `IEquatable<T>` partial** (the generated classes
are already `public partial class`) living in `src/Bortle.NINA.Emitter/Models/`, one file per
schema-generated group, named after its primary type — mirroring `schema/build.sh`'s
one-file-per-schema convention:

```
Models/
  SwitchDeviceInfoData.cs      // + ReadableSwitch, WriteableSwitch
  SafetyDeviceInfoData.cs
  WeatherDeviceInfoData.cs
  DomeDeviceInfoData.cs
  FilterWheelDeviceInfoData.cs // + FilterInfo
  RotatorDeviceInfoData.cs
  GuiderDeviceInfoData.cs      // + RmsError, RmsUnit
  FocuserDeviceInfoData.cs
  MountDeviceInfoData.cs       // + Coordinates, TrackingRate
  FlatPanelDeviceInfoData.cs
  CameraDeviceInfoData.cs      // + BinningMode
```

Each partial implements:

```csharp
public partial class Foo : IEquatable<Foo> {
    public bool Equals(Foo other) { /* compare every public property */ }
    public override bool Equals(object obj) => Equals(obj as Foo);
    public override int GetHashCode() => ...; // HashCode.Combine or a HashCode builder
}
```

Conventions used throughout:

* Compare every public property, in the same order they're declared in `Generated/EmitterModels.cs`.
* Strings compare with `StringComparison.Ordinal`.
* Nested reference-type properties (`SelectedFilter`, `RmsError`, `TargetCoordinates`,
  `TrackingRate`) compare with `object.Equals(a, b)` for null-safety, relying on that nested
  type having its own `IEquatable<T>` partial.
* `List<T>` properties compare with a local `ListEquals<T>` helper (`SequenceEqual` with
  null-vs-null/one-null handling); `List<List<double>>` (mount axis rates) gets a
  `NestedListEquals` helper on top of that.
* `GetHashCode` uses `HashCode.Combine(...)` when a type has ≤8 properties (its argument limit),
  otherwise a `HashCode` builder (`hash.Add(...)` per property); list properties contribute their
  `.Count` rather than a full traversal — cheap and still hash-contract-correct since it only
  needs to be consistent with `Equals`, not perfectly collision-free.

Handlers were updated to build the mapped payload *before* the dedupe check and compare that
against a `lastData` field of the payload type, instead of comparing the raw NINA SDK object
against a stashed previous one:

```csharp
public void UpdateDeviceInfo(FooInfo deviceInfo) {
    var data = new FooDeviceInfoData { /* map fields */ };

    // Skip duplicates from internal nina polling
    if (data.Equals(lastData)) return;

    emitter.Enqueue("foo", "device-info", data);
    lastData = data;
}
```

### Enforcement: drift test

`src/Bortle.NINA.Emitter.Tests/Models/ModelEqualityCoverageTests.cs` reflects over every
`Models` type implementing `IEquatable<T>` for itself, and for each of its public read/write
properties: builds a fully-populated baseline instance, clones it, mutates exactly that one
property to a different value, and asserts the clone no longer compares equal. A schema field
added later that isn't wired into the hand-written `Equals`/`GetHashCode` fails this test —
catching drift automatically instead of relying on anyone noticing.

### Alternatives considered

* **Post-process `Generated/EmitterModels.cs` in `schema/build.sh`** (e.g. `sed` `class` →
  `record`) — rejected as fragile against quicktype output changes and harder to reason about
  than an explicit, reviewable hand-written file.
* **Compare the raw NINA SDK types instead of the mapped payload** — not viable; those types
  (`SwitchInfo`, `CameraInfo`, …) aren't ours to add equality to, and NINA hands back a fresh
  instance on most polls regardless of whether anything changed, making reference equality
  always `false`.

### Consequence / maintenance note

These equality partials are **not regenerated** by `./schema/build.sh all` and must be kept in
sync by hand when a schema change adds/removes/renames a field on one of the types listed above.
`ModelEqualityCoverageTests` fails loudly if that's missed — run `dotnet test` after any schema
change touching these types.
